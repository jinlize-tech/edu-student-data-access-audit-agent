# 学员数据地图与权限审计领域指南

## 业务问题

学生和家长数据散落在表单、微信、CRM、教务系统和表格中，谁能访问、保留多久、流向何处常不清楚。

## 产品解决方案

盘点数据字段、系统、流程、角色与供应商，建立数据地图和最小权限建议，优先处理高风险访问。

## 输入质量要求

| 字段 | 名称 | 必填 | 质量要求 |
|---|---|---|---|
| `systems_inventory` | 系统与表格清单 | 是 | 系统、表格、位置和负责人 |
| `data_fields` | 学生数据字段 | 是 | 字段类别和必要性 |
| `user_roles` | 用户角色 | 是 | 岗位和访问需求 |
| `access_matrix` | 现有访问矩阵 | 是 | 谁可读、写、导出和删除 |
| `vendor_list` | 供应商与共享 | 否 | 接收方和用途 |
| `retention_policy` | 保留与删除规则 | 是 | 期限和责任人 |
| `student_data_categories` | 学生敏感数据类别 | 是 | 仅分类，不上传原始数据 |
| `change_context` | 变更背景 | 是 | 新系统、离职审计或季度复核 |

## 证据判断

- 用户原文优先于模型推断。
- 外部政策或公开事实应记录标题、发布机构、发布日期、URL、访问日期和适用范围。
- 无法核验时标记`EVIDENCE_UNVERIFIED`，不补造来源。
- 数据冲突必须并列展示，并说明对结论的影响。

## 人工复核

数据负责人/IT/法务应确认：学生数据字段、访问权限、供应商、日志和删除。未经确认的内容只能作为草案。

## 主要风险

不能直接操作真实系统；权限和保留需 IT/法务复核；数据地图本身也属于敏感资产，应受控。
